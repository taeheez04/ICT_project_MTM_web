설계
   1) 페이지 구상 (전체적인 느좋 감성 UI vs 게임(로딩 창 추가))
	- 메인 페이지 (우리 3명을 세워두고 고르기 vs 우리를 카드로 표현 (밑의 기능 표현이 좀 더 쉬움))
		내용 : 이름, 한줄 소개
		기능 : 카드에 마우스를 가져다 놓으면 아래 페이지들 중 고르기 가능
			/ 이때 다른 카드들은 흐려지고 마우스를 놓은 카드는 조금 커짐
	- 소개 페이지
		학교 홈페이지 마냥 상단에 눌러서 옮길 수 있게 하기
		모든 페이지 하단에 회사 위치 및 연락처 마냥 전번, 메일, 깃허브계정, 인스타계정
		1. 스토리
			내용 : 생애 타임라인
			기능 : 스크롤을 내리며 초, 중, 고, 입대 전, 현재
		2. 좋아하는 것
			내용 : 음식, 음악, 취미 공유
			기능 : 큰 틀 - 상단에 아이콘을 두고 넘어가는 형식 (민준 레몬 웹)
                                작은 틀 - 카드 형식으로 옆으로 화살표를 누르면 옆으로 넘어감 (창원대 와글)
		3. deep한
			내용 : 개인 MBTI-혈액형, 강점-단점, 고난-행복한 기억, 개인판단성격-타인판단성격
			기능 : 대비되는 내용을 간단히 적고 카드를 통해 앞 뒤로 보기
	- 미래의 우리? 설계?
		1. 목표
			내용 : 단기, 중기, 장기로 체크리스트 만들기 (추가 삭제를 위해서는 수정 페이지 need)
			기능 : 체크하면 진행 막대가 늘어남, 목표일까지 D-day 표시
		2. 자신이 생각하는 나의 미래
			내용 : 약 10년 후 미래를 그림 (직업, 사는 곳, 일과, 그때 나에게 보내는 편지)
			기능 : 연도 슬라이드, 10년 후 명함 (스크롤 생각 중)
	- 소통란 (방명록과 질문)
		내용 : 후기를 남기는 댓글을 남겨두고 당사자가 대댓글을 달 수 있는 느낌
		기능 : 배운 채팅 형식을 이용 (닉네임을 입력하지 않으면 댓글 불가능)
		방어기능 : 빈 글 금지, 도배 방지, 금칙어 필터, 숨김 처리
	- 수정 페이지 (숨은 get + 비밀번호 (SQL 해킹 방지) / 여기에 get, post, put, delete)
		-- 각자 계정 + 전체관리자 계정 vs 전체관리자 계정
		내용 : 데이터 수정, 체크리스트 변경, 소통 댓글 지우기 기능 및 대댓 달기

   2) api(저장되거나 여럿 공유하는 데이터)/라우팅 설계(주소창 post, get / 창에 따라 주소를 의미)
	-메인 : /main/MTM
	-소개 : /MTM/story/:id
	-미래 : /MTM/future/:id
	-소통란 : /MTM/talk/:id
	-수정 : /MTM/hideonweb/:id
   3) 데이터 구조 (ex 회원끼리 구분하는 핵심 데이터, 구조체 느낌)
